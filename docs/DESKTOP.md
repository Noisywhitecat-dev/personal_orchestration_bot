# 데스크톱 사용법

## 토큰 없이 첫 작업 체험하기

`AI Orchestrator-0.1.0-x64.exe`를 실행합니다. Node.js나 별도 서버 명령은 필요하지 않습니다.
최초 안내는 프로젝트 선택 → 실행 파일 확인 → 모드 → 모델/노력치 → 하네스 → 테스트 실행의 6단계입니다.
각 단계는 짧은 안내이며 프로젝트 등록과 설정은 화면의 해당 버튼으로 진행합니다.

1. **새 프로젝트**를 누르고 이름을 입력한 다음 **폴더 선택**으로 프로젝트를 등록합니다.
2. 상단이 **체험 모드**인지 확인합니다. 빈 폴더도 체험할 수 있습니다.
3. **프로젝트 준비 → 실행 전 점검**으로 환경을 확인합니다.
4. **체험 요청 채우기**를 누르고 요청을 읽은 뒤 **계획 만들기**를 누릅니다.
5. Claude의 계획과 완료 기준을 읽습니다. 범위/검증 방법은 접힌 정보에서 확인합니다.
6. **계획 승인하고 시작**을 누르면 Codex 코드 작성과 Claude 검토를 거쳐 완료됩니다.

체험의 변경 파일과 테스트·토큰은 예시이며 실제 AI 호출이나 코드 수정은 없습니다.
하네스 설치는 별도 파일 생성 기능이므로 체험 모드에서도 설치 버튼을 누르면 실제 파일이 생성됩니다.
안내 완료를 누르면 이후 자동으로 나타나지 않습니다. 기존 설정을 쓰던 사용자는 안내를 강제로 보지 않습니다.
왼쪽 **시작 안내**로 다시 열 수 있습니다.

## 화면 읽기

왼쪽은 프로젝트와 최근 작업, 가운데는 역할별 대화와 현재 단계의 주요 버튼입니다.
Claude는 갈색의 **기획 및 검토**, Codex는 녹색의 **코드 작성**으로 구분합니다.
오른쪽에는 단계·다음 행동·간단한 사용량을 표시합니다. 작은 창에서는 작업 정보가 대화 아래로 이동합니다.
실행 횟수, 세션 유무, 내부 이벤트, 상세 사용량과 진단 내보내기는 **상세 정보** 안에 있습니다.
요청/답변은 Ctrl+Enter로 보낼 수 있으며 버튼·메뉴는 Tab으로 탐색할 수 있습니다.

## 실제 AI 연결과 설정

1. Claude Code와 Codex를 설치하고 터미널에서 각 CLI 로그인을 완료합니다.
2. **앱 설정 → 사용 모드 → 실제 AI**를 선택합니다.
3. **고급 설정**에서 각 실행 파일을 선택합니다. PATH에서 실행 가능하면 기본 이름을 쓸 수 있습니다.
   Windows의 `.cmd` 래퍼는 `shell:false`에서 실행되지 않을 수 있으므로 정상 실행 가능한 `.exe`를 선택하세요.
   Codex Desktop 런타임의 `codex.exe`는 보조 실행 파일들이 같은 디렉터리에 있어야 합니다.
4. 간편 프리셋을 선택하거나 고급 설정에서 모델/노력치를 지정합니다. 빈 값은 CLI 기본값입니다.
5. **저장하고 다시 시작**을 누릅니다. 서버만 재시작하고 같은 창에 다시 연결됩니다.
6. **실행 전 점검**으로 경로, Git, 실행 파일, 로그인, 모델/노력치, 하네스 상태를 확인합니다.

모델 목록은 기존 Codex 로컬 캐시 및 앱의 호환 목록을 사용합니다. 지원하지 않는 노력치는 선택지에서
빠지며 저장 시에도 정규화됩니다. 점검은 모델을 호출하지 않으므로 실제 모델 접근 권한은 검증하지 않습니다.
로그인/명령 실패 시에는 명령 출력을 수집하지 않고 사용자가 확인할 다음 행동을 안내합니다.

간편 프리셋은 **자동**, **절약**, **균형**, **품질 우선**입니다. 모델과 노력치·실행 횟수만 제안하며
AI를 실행하지 않습니다. 프리셋 적용 시 토큰 상한은 제한 없음으로 돌아가므로 필요한 상한은 고급 설정에서
다시 지정하세요. 실제 요청 전 실행 요약을 확인하세요.
고급 설정에는 실행 횟수, 추가 질문/검토 횟수, Claude/Codex 토큰 상한과 제한 시간이 있습니다.
토큰은 실행이 끝나야 알 수 있어 한 번의 호출이 상한을 넘을 수 있습니다.

## 프로젝트 AI 하네스

**프로젝트 준비 → 프로젝트 AI 하네스 · 설치 미리보기**를 펼칩니다.
각 파일의 경로·상태·생성 내용을 확인한 뒤 **확인한 파일을 프로젝트에 설치**를 누릅니다.
생성 목록은 README의 하네스 목록과 같습니다. 프로젝트 전용 `.claude/skills`와 `.agents/skills`에
역할 스킬을 설치하고 `.ai-orchestrator`에 협업·검증·맥락 문서를 둡니다.
`AGENTS.md`와 `CLAUDE.md`는 없을 때만 짧게 생성하며 기존 파일을 자동 수정하지 않습니다.

충돌 파일은 보존하고 나머지만 설치합니다. 생성 예시와 기존 파일을 비교하여 필요한 부분을 직접 병합하세요.
변경된 관리 파일은 수정됨으로 표시되며 자동 업데이트하지 않습니다. 연결 폴더/정션은 차단됩니다.
하네스가 없거나 역할 스킬이 수정되어 확인되지 않아도 앱은 최소 역할 지시로 계속 동작합니다.

## 실패·재시작 후 복구

앱은 재시작 후 AI를 자동 재호출하지 않습니다. 실행 중이거나 후속 실행을 기다리던 작업은 중단됩니다.
질문 답변이나 계획 승인을 기다리던 작업은 남아 있으므로 사용자의 명시적 버튼으로 이어갈 수 있습니다.
실패 원인의 안내와 기존 변경 파일을 확인한 뒤 **새 작업으로 다시 요청**하세요. 새 요청은 추가 호출을 사용합니다.
설정 저장 중 진행 작업도 중단될 수 있으므로 먼저 완료를 기다리거나 중단하세요.

지원용 정보는 **상세 정보 → 진단 요약 복사 / 파일 저장**으로 내보냅니다.
세션 ID, 경로, 사용자 요청, AI 원문, diff, 비밀값을 빼고 상태·횟수·사용량만 제공합니다.

## 데이터와 패키지

기록과 설정은 Windows의 사용자 애플리케이션 데이터 폴더에 저장됩니다. 실행 파일을 옮겨도 유지됩니다.
프로젝트 하네스는 사용자가 고른 프로젝트 안에만 생성합니다. 원본 diff/CLI 출력은 SQLite에 보관하지 않습니다.
CLI 자체가 만드는 전역 세션 기록은 각 CLI가 관리합니다.

개발자는 `npm run desktop:dist`로 `app-release/AI Orchestrator-0.1.0-x64.exe`를 만들 수 있습니다.
개발 실행은 `npm run desktop`, 설치형 패키지는 `npm run desktop:installer`입니다.
