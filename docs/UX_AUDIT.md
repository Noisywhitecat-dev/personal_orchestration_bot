## 검증 근거

- 메모리/SQLite: 실행 중·승인 대기 삭제 차단, 완료 작업 삭제, 다른 작업과 프로젝트 보존.
- SQLite: 중간 오류를 주입해 메시지·사용량·실행을 포함한 롤백 검증.
- HTTP: 명시적 확인, 교차 origin 차단, 중단 후 삭제, 삭제 후 404.
- SSE 공개 이벤트, 삭제 후 선택 복구 및 마지막 작업 삭제 시 빈 화면 데이터 복구.
- React 정적 렌더링: 상태별 삭제 버튼, 확인창 기본 취소 포커스·이스케이프, 사이드바 실제 모델/노력치와 미보고 한도.
- Electron lifecycle 대역 + 실제 Fake 서버: 안내 완료가 서버를 유지하며 모델 설정 저장은 재시작함을 확인.

### 검증 중 추가 수정

- 삭제 확인창 제거 후 포커스가 사라지던 문제를 수정했다. 종료 시 원래 버튼으로 복귀하며,
  대상 버튼이 사라진 경우 새 작업 버튼을 사용한다. Tab/Shift+Tab 이동을 확인창 안으로 제한했다.
- 대화 자동 이동은 scrollIntoView 대신 대화 컨테이너의 scrollTo를 사용하여 조상 페이지까지 움직이지 않게 했다.
- 상대 staticDir를 절대 경로로 정규화했다. Windows에서 dir의 슬래시와 join 결과의 역슬래시가 달라
  정상 index.html도 403 Forbidden이 되던 문제를 회귀 테스트로 검증했다.
- 고급 한도 클릭 때 자동화 도구의 자동 스크롤로 페이지가 이동하는 현상은 실제 화면 위치 클릭으로
  구분했다. 실제 클릭에서는 상단/입력/실행 버튼이 유지되어 추가 CSS 변경은 하지 않았다.

### 검증 범위

위 브라우저 시나리오는 완료했다. 실제 OS 한글 IME의 후보창/언어 전환은 자동화하지 않았으며,
조합 중 전송 방지는 브라우저에서 실제 React 핸들러로 전달한 합성 키보드 이벤트로 검증했다.
Electron IPC/내장 서버 재시작은 실제 Fake 서버를 사용하는 lifecycle 자동 테스트로 검증한다.
네이티브 파일 선택기, 실제 계정 로그인/사용량 조회, 실제 AI 생성은 이번 범위에서 실행하지 않았다.
운영 DB·외부 프로젝트·전역 설정은 변경하지 않았고 새 의존성도 없다.

초기 자동 접속에는 ERR_BLOCKED_BY_CLIENT가 있었고, 이후 직접 연 페이지에서 서버의 403을 확인했다.
이를 동일한 원인으로 단정하지 않는다. 최종적으로 권한 확대 없이 경로를 수정해 정상 접속과 UI 검증을 완료했다.
